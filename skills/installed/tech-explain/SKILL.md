# 讲原理

## 调用边界

只有同时满足以下条件时才使用本技能：

1. 用户在当前请求中明确调用 `$tech-explain`。
2. 当前任务是解释某个对象的技术原理，或撰写技术原理报告。

不要因为遇到技术问题、代码、README、操作手册、说明文档或普通问答而自动使用本技能。安装不代表永久开启。一次明确调用只覆盖用户当次指定的范围，不延伸到后续请求，也不连带启用 `$plain-chat` 或其他技能。

本技能既可以从零生成解释或报告，也可以改写、补全或审阅已有的原理说明。不要把任务限制为润色现成文本。

## 目标

让读者理解系统为什么这样工作、信息怎样流动、约束从哪里产生，以及结论在哪些条件下成立。清晰比压缩更重要；技术准确性、必要细节和可核查边界优先于“简单好懂”。

## 工作方式

1. 确认需要解释的对象、读者背景、关注层次和交付形式。若缺失信息会实质改变结论，先指出假设或询问。
2. 先界定系统边界和关键概念，再说明组成部分、状态或数据、控制关系、因果链和工作顺序。
3. 解释“为什么”时给出支撑机制，而不只复述现象或功能。区分设计目的、实际机制、经验规律和推测。
4. 只在有助于准确理解时使用公式、代码、伪代码、推导、图示或专业术语；给出必要定义，并保持同一概念的称呼一致。
5. 检查事实、条件、否定、范围、时序、比较对象和不确定程度。确认没有用更短的说法改变原意。
6. 按用户需要输出直接解释或结构化报告。结构应服务于问题，不强制套用固定章节。

## 技术表达原则

- 一个概念尽量使用一个稳定名称；避免为了文采轮换同义词，造成读者误以为是不同对象。
- 优先使用明确主语和直接动词。行动者未知或不重要时，可以保留被动表达，不要虚构主语。
- 一句话承载一个主要判断。复杂关系可拆成步骤、条件列表、公式或代码，但不要切断必要的逻辑连接。
- 保留必要术语，并在首次出现时按读者背景解释。不要为“说简单”牺牲精度。
- 删除无信息的铺垫、营销形容词、名词堆叠和重复结论；不要删除安全条件、例外、作用域或关键限定。
- 不追求最短文本。句子已经清楚时停止压缩。

上游 ASD-STE100 技能中的英文句长规则可作为英文表达的诊断线索，不是本技能的硬性输出限制。中文解释不套用英文单词数限制；公式、代码、推导和必要术语也不受该限制。

## 不确定性与事实保护

- 不添加来源没有提供、也无法可靠推导的机制、数字、性能结论、因果关系或实现细节。
- 保留“可能、通常、在……条件下、尚未验证、据称”等信息强度。不要把相关改成因果，把计划改成完成，把推测改成事实。
- 明确区分已知事实、由已知事实推导的结论、合理但未验证的假设，以及当前未知项。
- 若简化会损失精度，保留较长表达并指出原因。
- 不宣称符合官方 ASD-STE100 词典。上游未包含该受限词典；需要航空航天级合规时，应以官方标准和词典逐项核对。
